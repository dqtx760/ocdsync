# Codex 使用技巧与工作流

本文档总结提升 Codex 使用效率的实用技巧和常用工作流。

---

## 基础技巧

- 明确目标：在 Prompt 中写清楚输入、输出和约束。
- 提供上下文：给出文件路径、现有结构、错误日志，减少猜测。
- 拆分任务：把大任务切成若干小步骤，逐步推进。
- 保持一致：统一命名、风格、注释方式，避免混用。

---

## Prompt 设计

### 结构化 Prompt 示例

1. 背景：项目使用什么技术栈和架构。
2. 任务：希望 Codex 完成什么目标。
3. 输入：提供哪些文件、日志或数据。
4. 输出：期望返回什么格式，例如代码、步骤、报告。
5. 约束：禁止改动哪些文件、遵循哪些规范。

### 提升质量的技巧

- 要求 Codex 先给方案再写代码。
- 明确测试要求：正常路径 + 边界条件 + 异常路径。
- 用示例说明期望输出格式。
- 指定可接受改动范围，避免波及无关文件。

---

## 常用工作流

### 1. 需求到实现

- 先整理需求要点。
- 让 Codex 列出实现步骤。
- 逐步生成代码并验证。
- 完成后要求 Codex 给出回归建议。

### 2. 调试流

- 提供错误信息和复现步骤。
- 请 Codex 给出可能原因列表。
- 让 Codex 给出排查命令与修复方案。
- 修复后补充测试防止复发。

### 3. 重构流

- 说明重构目标和限制。
- 让 Codex 给出重构计划。
- 增量修改，每步都运行验证。
- 最后让 Codex 检查命名、结构、注释。

### 4. 测试流

- 提供函数签名、业务规则和边界条件。
- 让 Codex 生成测试用例。
- 人工补充关键场景。
- 用测试结果反馈优化实现。

---

## 协作习惯

- 每次对话保持单一主题。
- 长任务使用检查点，阶段性确认结果。
- 对重要改动做 diff 审查。
- 把有效 Prompt 记录下来形成模板。

---

## 效率提升建议

- 先写接口规范，再让 Codex 填充实现。
- 优先修复结构问题，再优化细节。
- 用简短明确的指令，避免模糊描述。
- 生成后自己再做一轮精修。
