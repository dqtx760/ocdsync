Codex 5 个实用技巧

1. 🧠 开启 Memory，让 Codex 记住你的工作习惯

Memory 的价值不只是"记住聊过什么"，而是记住你反复验证过的做事方式。

比如你每次排查 Bug 都习惯结合代码和数据库一起查，开启 Memory 后，以后只需把 Bug 现象告诉它，它就会自动按这个路径排查。

💡 前提：你自己的提问方式要稳定可复用，它才能沉淀出有价值的习惯。

2. 📋 写好 AGENTS.md，固化项目规则

在项目根目录创建 AGENTS.md，把技术栈、常用命令、禁止修改的目录、代码风格等写进去，Codex 每次启动都会读取。

这样可以避免它"不知道怎么跑测试"、"随便改了不该改的文件"等低级错误，团队使用时效果尤为显著。

3. 🔄 用 CLI 替代 MCP，更省资源和 Token

MCP 会拉起大量后台线程，执行过程直接进入大模型上下文，导致 Token 消耗高、速度慢。

切换到 CLI 模式后：
· 电脑资源占用更低
· Token 消耗明显减少
· 体感速度更快

以 Playwright 为例，截图、控制台输出等走结构化文件输出，比 MCP 更轻更高效。

4. 📝 先计划再执行，用"四段式提示词"

不要直接让 Codex 改代码，先让它给计划：

目标：你要完成什么
上下文：相关文件、错误日志
约束：不能做什么
完成标准：怎样算完成

复杂任务尤其适用先读 → 先计划 → 再改 → 最后验证的节奏，大大减少"改多了"或"改错了"的情况。

5. 🔍 任务完成后让 Codex 做"自审"，而不是自己盯 diff

每次 Codex 改完代码，不要自己一行行看 diff，而是让它先做一轮自查：

请自查刚才的改动：
· 是否满足原始需求？
· 有没有改到无关的文件？
· 有没有潜在 bug 或回归风险？
· 缺不缺测试？

请按"阻塞问题 / 非阻建议 / 验证结果"三类输出。

这样做有两个好处：
· 它能发现自己的错误，比你肉眼扫 diff 更全面
· 你可以把精力放在"阻塞问题"上，非阻塞的建议性问题让它自己处理
