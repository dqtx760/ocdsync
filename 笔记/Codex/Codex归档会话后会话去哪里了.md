# Codex 归档会话后，会话去哪里了？

---

## 归档是什么

归档会话后，对话窗口并没有被删除，而是被移到了历史记录中。

简单说：归档 = 从侧边栏的活跃列表中隐藏，但对话数据仍然保留。

---

## 归档 vs 删除

- **归档**：从侧边栏隐藏，数据保留，可以随时恢复。
- **删除**：彻底清除，无法恢复。
- **取消归档**：放回侧边栏，恢复为活跃会话。

---

## 去哪里查看归档的会话

1. 打开 Codex 桌面 App。
2. 在侧边栏顶部或账号菜单中，找到「历史记录」或「Archived」入口。
3. 在列表中可以浏览所有归档的对话。
4. 找到对应的会话，选择「Unarchive」（取消归档）就能把它放回侧边栏。

注意：不同版本的 Codex 桌面 App，入口位置可能略有不同。


---

## 典型操作流程

1. 打开 Codex 桌面 App。
2. 在侧边栏找到需要归档的会话。
3. 右键或点击会话旁的菜单按钮，选择「Archive」（归档）。
4. 该会话从侧边栏消失，但数据仍保留在历史记录中。
5. 需要时，进入历史记录，找到并取消归档。

## 小结

---

## 会话窗口的本质：上下文窗口

每个 Codex 会话本质上是一个上下文窗口。每次新对话都是全新上下文——Codex 不记得之前聊了什么。因此保持单一主题，才能让上下文发挥最大价值。

### 核心原则

一个会话 = 一个独立任务或主题，比如：

- 学习 Codex 笔记整理 → 一个会话
- 配置国产 API → 一个会话
- 给项目写 AGENTS.md → 一个会话
- 排查某个 bug → 一个会话

### 什么情况可以在一个会话里聊多个话题

- 话题之间有关联性（比如聊 Codex 学习路径，然后延伸到 AGENTS.md 写法）
- 每个话题都很短，上下文不会被稀释
- 你不想维护太多会话

### 什么情况应该开新会话

- 话题完全不相关（比如一边学 Codex，一边调试另一个项目的 bug）
- 当前对话已经很长了，上下文被早期内容稀释，后面的问题质量下降
- 需要不同的约束或环境（比如一个会话用只读模式分析，另一个要写代码）

### 一个实用判断方法

> 如果你发现自己要跟 Codex 重新解释一遍之前的背景，说明这个会话应该拆了。

### 一句话总结

**按主题分，不按念头分。** 同一个主题下的延伸不需要开新会话，但跨主题就果断拆。

- 归档不是删除，只是隐藏。
- 随时可以在历史记录中找到并恢复。
- 只有主动「删除」才会彻底清除，且不可恢复。
